# MX Master 4 side wheel

Restart the updated app, select **MX Master 4**, and press **Save profiles**. Save configures the side wheel to send native horizontal scrolling to Linux and verifies the result. No extra mouse button needs to be held. Test with the cursor over a spreadsheet, wide editor or another area that supports horizontal scrolling.

**Scrolling → Side wheel** shows whether the live device is diverted or using native horizontal scrolling. **Reverse side wheel** is saved with each profile. The existing Natural scrolling option also affects the side wheel; the Scroll speed control applies to both wheels. Saving starts the Master 4 helper even when Automatic restore is off, so saved side-wheel behavior continues while the window is closed. The helper checks side-wheel state every five seconds, including when the Bolt receiver stays connected while the mouse sleeps/wakes. It only repairs side-wheel state on these periodic checks, preserving DPI cycling and physical main-wheel mode changes.

Older Master 4 profiles default to native side-wheel scrolling in the normal hardware direction. Other mouse models do not get side-wheel settings. Saving, duplication, reset, discard, JSON transfer and previous-setup restoration include the direction setting.

Previously Mouse Studio never configured the thumb wheel. A device left diverted to HID++ could therefore send reports that the application did not consume, producing no ordinary scroll events. The new native restore path queries HID++ feature `0x2150`, reads two setting bytes with function `0x10`, clears the diversion bit and sets the requested direction with `0x20`, then checks readback. It preserves other bits and attempts to restore the complete original state on failure. The implementation follows [Solaar's thumb-wheel settings definitions](https://github.com/pwr-Solaar/Solaar/blob/master/lib/logitech_receiver/settings_templates.py).

This native path is the default. Existing `/etc/logid.cfg` is not edited. If another utility repeatedly diverts the side wheel, let Mouse Studio manage this control exclusively.

Automated tests cover diversion recovery, normal/reversed direction, reserved-bit preservation, readback failure/rollback, unsupported hardware preflight, live-state decoding, old profiles, reconnect/wake checks, preservation of cycled DPI, and UI save/discard. ## Remapping the side wheel to actions (MX Master 4)

**Scrolling → Side wheel → Remap to actions** replaces horizontal scrolling, per profile, with one action for *Scroll left* and one for *Scroll right*. Choose a preset (Volume, Zoom, Workspaces, Browser tabs) or set each direction to a keyboard shortcut, application, command or workspace; a direction left on Default does nothing. Macros and Cycle DPI are not accepted. **Wheel travel per action** sets how many reported wheel units trigger one action (1-200). **Swap directions** exchanges the two actions. **Horizontal scroll** returns to the native behavior above. Old profiles load as Horizontal scroll, and the setting is included in Save, duplicate, reset, discard, JSON import/export and previous-setup restoration. Other mice reject it.

How it works: the existing extra-button helper (`src/hardware/buttons.rs`) diverts feature `0x2150` by setting only bit 0 of the first status byte (function `0x20`, verified by a `0x10` readback, other bits unchanged), reads the function-0 rotation notifications from the same HID++ stream it already listens to, converts rotation into left/right steps and runs the saved action through the same Lua action expressions used by buttons (`runtime::action_expression_for`). Stale events are discarded unless the setup token, profile id and profile token still match. Large bursts are capped (16 steps per report, 8 actions per compositor call).

Recovery: saving a remapped profile makes the helper mandatory (like extra buttons) and Save reports an error if the helper is not ready. Every five seconds the helper verifies the wheel is still diverted and redoes it after a Bolt sleep/reconnect, dropping partial rotation. On profile change, Horizontal scroll, service stop or any helper error, the helper releases the diversion; a failed release is retried and ownership is kept until it succeeds. The periodic native repair that normally clears diversion is skipped only while the active profile is remapped, so the two never fight; switching to a native profile clears it again within a poll. If the helper is killed abruptly the wheel stays diverted until the helper restarts (systemd restarts it) or a native profile is applied; Mouse Studio treats an already-diverted wheel as its own because it is documented as the exclusive manager of this control.

Protocol sources: [logiops `ThumbWheel.cpp`/`ThumbWheel.h`](https://github.com/PixlOne/logiops/blob/master/src/logid/backend/hidpp20/features/ThumbWheel.cpp) (function 1 status `[diverted, flags]`, function 2 set `[divert, invert]`, event 0 with big-endian `i16 rotation, u16 timestamp, u8 status (0 inactive, 1 start, 2 active, 3 stop), u8 flags`) and [Solaar `ThumbMode`/`ThumbInvert`](https://github.com/pwr-Solaar/Solaar/blob/master/lib/logitech_receiver/settings_templates.py) (read `0x10`, write `0x20`, masks `0x0100`/`0x0001`).

**Not verified on hardware** (this session had no `/dev/hidraw*` access and performed no writes): that a positive rotation is *right* (use Swap directions if reversed); how many reported units one physical notch produces (tune Wheel travel per action); whether the firmware applies the native Reverse bit to diverted events (the Reverse checkbox is hidden while remapping and the bit is left untouched); and the Hyprland workspace commands in the Workspaces preset (`hyprctl dispatch workspace e-1` / `e+1`). Automated tests cover the byte-level diversion, readback/rollback, wake re-diversion, rotation accumulation, direction flips, flood caps, stale-event guards, the generated Lua, profile validation and persistence, and the restore/native-repair interplay.
